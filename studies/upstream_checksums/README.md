# Pending upstream CI-benchmark reset for the transverse-boundary fix

**Why this directory exists.** The `LaserDeposition` transverse-boundary fix
(`warpx-cda` c817b63, `TEST_PLAN.md` §2.8) changes three 2D CI checksums, so
`warpx-cda/Regression/Checksum/benchmarks_json/` must be reset or those tests fail.
Writing into that directory was **blocked by a permission rule** in the session that
produced the fix, so the recomputed values are parked here instead of being lost.

**To apply** (from `warpx-cda`):

```bash
cp /home/hhelal/LaserProdShock/studies/upstream_checksums/test_2d_laser_deposition_*.json \
   Regression/Checksum/benchmarks_json/
```

The three files are byte-for-byte what `checksumAPI.py --reset-benchmark` would have
written (`json.dumps(..., indent=2, sort_keys=True)`), so applying them is equivalent to
running the sanctioned tool — they were generated by `Checksum(...)` on the post-fix
plotfiles, not hand-edited.

## Why resetting is legitimate rather than papering over a regression

The **pre-fix** binary, run at the CI configuration (2 MPI ranks, `OMP_NUM_THREADS=1`),
reproduces every committed benchmark to **≤4×10⁻¹⁶** — machine precision. So this build
*is* the CI reference, and the differences below are the fix, not the environment.

(Getting that right mattered: at 1 rank the same pre-fix binary disagreed with the
committed benchmarks by up to **24 %**, because the operator applies random momentum
kicks and the RNG stream depends on the decomposition. Had that been mistaken for the
fix's effect, these values would have been garbage. The test's `nprocs` is declared in
`Examples/Tests/laser_deposition/CMakeLists.txt` — read it before regenerating anything.)

## What changes, and by how much

| benchmark | worst rel. change | why |
|---|---|---|
| `test_2d_laser_deposition_oblique` | **+164 %** | 30° tilt, rays drift 2.9 transverse domain widths — the decisive case |
| `test_2d_laser_deposition_focus` | +4.7 % | converging beam diverges past focus and grazes the transverse face |
| `test_2d_laser_deposition_gaussian` | +2.2×10⁻⁵ | only near-critical reflection off a noisy `grad n_ref` kicks rays transversely |
| `test_1d_laser_deposition{,_ramp}` | **0 (bit-identical)** | no transverse dimension; the axis still clamps and terminates |

`particle_weight` and all `E`/`B` components are unchanged; only `particle_momentum_*`,
`particle_position_*` and `j*` move.

**The direction is a physics check, not an accident.** Σ|u| *rises* because the same
absorbed energy now spreads over 8× more electrons instead of piling into one column, and
|u| ∝ √E is **concave**: predicted √8 = 2.83×, measured 2.46×. A fix that merely shuffled
indices would have left the sum alone.

**Do not "fix" a future failure of these tests by resetting again** without first checking
that the pre-fix-equivalent binary still reproduces the committed values at the declared
`nprocs`. That check is the only thing separating a legitimate reset from erasing a
regression.
